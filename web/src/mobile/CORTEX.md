# mobile/ — Cortex mobile v3 (scheme-mobile.dc.html)

The mobile client shell + the full v3 screen set. The SPA renders a **full-bleed, edge-to-edge**
viewport with a bottom four-Tab nav (**会话 / 线程 / 任务 / 项目**); the active screen swaps through
`<Outlet/>`. Desktop is a separate router (see `RootRouter`) and is byte-identical. **The OS draws its
own status bar, dynamic island, home indicator and screen corners — we do NOT paint a mock device
frame.** Screens reserve the OS chrome via `env(safe-area-inset-*)`: headers pad the top inset; the Tab
bar / composer / non-Tab bottom gutters pad the bottom inset. Design source (GROUND TRUTH):
`context/projects/cortex-self/design/ref/scheme-mobile.dc.html` (sections 1a–1r plus §2 composer
multi-line growth / full-screen editor). Raw px/hex/font by
design (§8.3, `@ds-adherence-ignore`) — the mobile palette is not in the light `proto.*` token set.

## v3 structure

The **project is the global scope**: 会话 / 线程 / 任务 only show the current project (a passive QN
scope tag in the header); the **项目 tab** shows project info + switches the current project. The 项目
tab carries an amber `需要你` count badge (pending approvals). Copy is per-screen and inline
(`const COPY = { en, zh }` + `pickCopy(useLang(), COPY)`) — the shared `i18n/vocab.ts` only holds the
tab label `project` (v3 screens deliberately avoid the vocab bottleneck).

## v3 screens (`v3/`)

Screens use `M<X>Screen.tsx` containers, `M<X>View.tsx` presentation, and pure `m-<x>-vm.ts` logic where needed. Tests focus on VM/state behavior and critical action availability rather than copy, color, dimensions, or broad static-render snapshots. All screens render real tRPC data with honest placeholders for absent contract fields.

## Notes

- **Image/video lightbox** (`features/media`, shared with desktop): `MediaViewerProvider` is mounted in
  `MobileShell`; the composer chips (`MChatView` `ComposerChip`, local `URL.createObjectURL` preview)
  and stream attachment tiles (`AttachmentTile`, auth-fetched thumbnail — user AND agent media) open the
  full-screen **modal** previewer via `useMediaViewer().openMedia` instead of downloading / a new tab.
  Plain files keep the download tap.
- **Render switch**: `src/RootRouter.tsx` mounts `mobileRouter` (mobile) or the desktop `router`.
- **Live data / no backend change**: every screen uses the existing `ui-service` tRPC contract; no
  agent-server change was needed for v3 (the contract already covered it).
- **`screens/` is legacy helper storage only.** Unrouted v2 containers/components were removed. The remaining files are imported by v3: `mobile-session-vm` stepper/divider/tool chips, `MobileThreadStepper`, and `mobile-machines-vm` card/time helpers.
- The unused `IOSDevice` mock-device specimen was removed; the native shell owns device chrome.
- Verified: `pnpm`/web `tsc --noEmit` EXIT 0; web `vitest src/mobile` all green; `vite build` EXIT 0.
- **Smooth reveal verified in a real browser at a phone viewport** (390×844 CSS px, DPR 3, touch
  emulation, headless Chrome over CDP): the pacing rule itself is pure and unit-tested, but the rAF
  integration is not reachable from the `node` vitest env, so it was driven against the REAL
  `MChatView` with a simulated delta source at the measured CLI cadence (92 chars / 350ms), sampling
  the rendered DOM every frame. Result over 462 frames: **54.3 text updates/second vs the source's
  2.9**, median **4 characters per frame**, the drawn text a prefix of the buffer on **every** frame
  and never moving backwards, lag holding at a median 81 / max 146 characters instead of
  accumulating, and the handover settling exactly (1840 of 1840 characters, no trailing animation).
  Switching stream identity mid-reveal settles rather than carrying progress: a single 330-character
  frame at the switch, still no prefix violation. Under `--force-prefers-reduced-motion` there is no
  pacing at all — 2.5 updates/second, whole 92-character chunks, max lag 1 character. The same
  harness confirmed the pending row (dimmed `rgba(255,255,255,.55)` text on the **unchanged**
  `rgb(25,28,34)` bubble at full opacity, pinned below the settled rows) and the running composer
  (Send 38px at x=284 beside Stop 46px at x=330, text field still 178px wide on a 390px viewport).
