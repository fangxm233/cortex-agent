# features/workbench/ — Workbench app-shell frame + Left Rail + Center Chat + Right Panel (Stage-R RB)

The `/workbench` route is the app-shell **frame** — the load-bearing seam every workbench pane
composes into (plan §8.6 RB). Rebuilt 1:1 from `design/ref/prototype.dc.html` L39–100: a single
`display:flex;height:100vh;min-width:1280px;overflow:hidden` row holding three panes — **340px**
LeftRail (flex:none — widened from the prototype's 240, 2026-07-16) /
**fluid** CenterChat (flex:1;min-width:0) / **400px** RightPanel (flex:none).
CenterChat (89e7) + RightPanel (1e96) are real 1:1; the LeftRail was **refactored to the 22a
dual-zone scheme** (scheme.dc.html §22a, 2026-07-16) — PROJECTS zone on top, current-project
SESSIONS below, draggable divider.

| `reveal-pacing.ts` / `reveal-pacing.test.ts` | **Pure** pacing math for the smooth reveal of streamed assistant text (TDD, 32 tests). The backend delivers token-level deltas, but the CLI upstream batches them — measured against a real 4689-character reply: 51 deltas of ~92 chars (median 90, max 131) every ~350ms (median 361, p90 412), i.e. **2.9 updates/second**, each landing about a line. Appending each delta whole therefore reads as a staircase, so the row reveals the buffer it ALREADY holds at a steady character rate instead. `stepReveal(revealed, total, dtMs)` is the rule: reveal at `backlog / one source interval`, so the reveal runs about one interval behind arrival and never drifts further as the reply grows; past a **catch-up knee** (two chunks) the drain window shrinks in proportion to the overshoot, making the rate grow with the SQUARE of the backlog so a burst is worked off in a few frames; a **floor** (120 chars/s) keeps the tail of a block off the exponential decay; beyond the **hard bound** (eight chunks) nothing is paced at all and the whole buffer is shown in one step — the case a session switch, a backgrounded tab (no rAF, so no frames) or a reconnect lands in. Fractional by design (flooring per frame would systematically drag the rate slow). `carryReveal(prevText, nextText, revealed)` keeps progress only across a real EXTENSION of the buffer — a new block or a rewind restarts at zero — and `rebaseReveal(prev, next)` adds the stream-identity rule: a changed `streamKey` settles to the full buffer instead of pacing onward from another session's progress, compared by identity rather than content so two replies opening with the same words cannot bleed. `revealedText` slices. The whole module is frame-agnostic (the caller supplies elapsed time), so the invariants — prefix-only, bounded lag under backlog, instant settle — are unit-testable in the `node` vitest env, including a frame-by-frame simulation of the measured cadence. |
