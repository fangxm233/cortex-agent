`agent-server/src/events/` — S4 EventBus and async observability infrastructure.
Only depends on core/, constructed and connected by entry/app.ts, not yet connected to any production publishers (S5/S6 handle that).

| filename | role | function |
|---|---|---|
| `event-types.ts` | types | CortexEvent union type (user events + 2 meta events; incl. `execution.log` live log-tail stream, `session.message` S4 chat live stream — sessionId/channel/role/text, published at agent-runner's conversation-history append points, plus the optional `pending` marker on a user message written into a live turn's backend but not yet read by the model (no history entry yet — a provisional row the client pins below whatever the agent is currently emitting), and `session.status` — sessionId/channel/running (+ optional `backgroundRunning`), the REAL per-turn running indicator emitted by agent-runner at turn start/finally; `backgroundRunning` marks the web bg-hold window (foreground turn done, a background task still running — running stays true) so the Web composer shows a distinct "background" state instead of sealing idle (web-bg-hold.ts); and `session.turn` — sessionId/channel/numTurns, the REAL live agent-turn count emitted by agent-runner on each turn_progress so the Web composer shows turns that grow as the agent works; and `session.message.delivered` — sessionId/channel/messageTs/committedTs, the mid-turn injection COMMIT: a message injected into a live turn and surfaced immediately as pending has now been consumed by the model (a stdin write only queues it inside the backend, for seconds or until after that turn's result), or its injection window closed without that happening. It enters conversation history at that moment, not at the write: `messageTs` keys the pending row, `committedTs` is the history ts a transcript refetch returns, so the client re-keys the row and the live and fetched rows dedupe as one; and `session.rewound` — sessionId/channel/turnIndex, message edit + rewind (sessions.rewind): the transcript changed SHAPE (turns ≥ turnIndex rolled back), a content-free hint so live clients drop buffered live tails + refetch; and `system.notice` — level/text/title, the encapsulated admin/system broadcast (startup, restart, profile/config/machine hot-reload, disk, rate-limit) published via `domain/system/system-notice.emitSystemNotice` and surfaced by the Web notification toaster; and `config.changed` — a typed, content-free successful-config-reload hint (`section:'profiles'`) that lets Web clients invalidate the authoritative `config.get` snapshot without parsing the human notice; and `session.message.delta` — sessionId/channel/blockId/text/seq, the token-level preview of an assistant text block still being generated: `text` is the INCREMENT since that block's previous event, `seq` counts from 0 per block, and the `session.message` carrying the same `blockId` supersedes it as the authoritative text) + CortexEventInput (distributive Omit) |
| `event-bus.ts` | core | EventBus: subscribe / publish (synchronous fan-out) / registerCloseHook / close() |
| `event-logger.ts` | observability | createEventLogger: ring buffer 1024, 100ms flush, daily rolling jsonl, 14-day retention, CORTEX_EVENT_LOG=off escape hatch. Skips META_EVENTS (re-entrancy) and TRANSIENT_EVENTS — `session.message.delta`, dozens per reply and fully repeated by the complete `session.message`, so logging it would multiply the daily jsonl and evict real events from the ring buffer |
| `event-replay.ts` | debug | CLI: `node events/event-replay.ts --date YYYY-MM-DD [--type xxx]` |
| `index.ts` | export | External barrel: EventBus / Subscription / CortexEvent / CortexEventInput / createEventLogger |
