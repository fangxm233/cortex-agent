    Cortex¶

    An agent workbench for auto research, self-improvement loops, and other work that runs for days. You give it a mission with a success criterion. It plans the work, runs it with a team of agents across your machines and GPUs, keeps every result as plain files in your project, and checks the outcome against what you agreed, asking you only when a decision is yours to make.

    Why Cortex?¶

    A coding agent in a terminal is built around one session: one task, one machine, done within the hour. Auto research and recursive self-improvement (RSI) need more. A study runs for days and outlives every session in it. Its results have to be kept and compared run after run. The work splits among several agents, and the experiments run on GPU servers rather than on the machine the agent started from.

    Cortex runs coding agents (Claude Code, or PI with the provider you already pay for) as a long-lived service built for that kind of work:

    • Work continues across sessions — mission, status, and decisions live as plain files rather than in a chat history that accumulates and decays, so a new session picks up where the last one stopped.
    • Results are kept — every experiment is its own record of what ran, what came out, and what it means; confirmed findings and cross-experiment patterns collect beside them (Memory).
    • Agents work as a team — a lead hands bounded pieces to subagents and persistent workers that start with a fresh context, and keeps a live board of where the work stands (Team Mode).
    • Agents manage model training across your machines — they check which GPUs are free, launch training and evaluation runs on any connected machine, and wait on them without polling (Cross-Machine, Waitpoints).
    • The setup itself can improve — skills, rules, hooks, and Cortex's own source are files the agents can change, inside a safety boundary you write. Cortex itself is developed entirely inside Cortex.

    How Cortex compares¶

    Cortex does not replace Claude Code, Codex, or PI. It runs them as a long-lived service: work that lasts for days, GPU servers across machines, and fewer tokens spent along the way. Claude Code and PI are its backends and run on the subscriptions you already have, including a ChatGPT plan through PI.

    Features¶

    • Plans and approvals — non-trivial work starts from a plan you approve; questions, decisions, and operations that need sign-off arrive as cards you answer in place (Safety & Approvals).
    • Subagents and team mode — bounded work goes to subagents with a clean context; with team mode on, a session can lead persistent worker sessions (Team Mode).
    • Boards for long work — a long task keeps a live status page beside the conversation, showing its state, plan, what needs you, and the decisions taken (Boards).
    • Structured project log — every project keeps mission, roadmap, status, experiments, knowledge, patterns, and decisions as plain files (Memory).
    • Scheduling and waitpoints — schedule Cortex to scan, digest, or sweep on a recurring basis, and let a waitpoint wake a session when a training run, build, or evaluation it launched finishes (Scheduling, Waitpoints).
    • One agent across your machines — connect any Mac, Windows, or Linux machine via cortex-client; the workbench shows each machine's CPU, memory, disk, and per-GPU load and processes (Cross-Machine).
    • Editable skills and plugins — skills are plain SKILL.md files that Cortex and you can write, override, or revert, on disk or from Settings → Plugins; execution environments choose which plugins, rules, and tools each session gets (Skills & Plugins, Configuration).
    • Rebuilds itself from source — with CORTEX_REPO pointing at a source checkout, Cortex rebuilds, reinstalls, and restarts itself when its code changes (Hot rebuild).
    • A browser the agent drives — agents open, read and operate web pages in a Chrome on the server or on your own machine; you watch it live and take over for logins (Agent Browser).
    • Web, native app, chat, and terminal access — use the browser workbench, Linux/macOS/Windows desktop app, Android app, Slack, Feishu, or TUI against the same server. The workbench shows sessions, workers, boards, approvals, machines, and project memory side by side.

    Quickstart¶

    The desktop app installs and starts a Cortex server on macOS, Linux, or Windows without a terminal. From a terminal:

    npm install -g @cortex-agent/server
cortex init
cortex ui enable
cortex daemon

    See Quickstart for detailed server and chat-platform setup. Once the server is running, open the workbench at http://127.0.0.1:3004 on the server, use Browser Access to reach it from elsewhere, or connect a native client as described in Desktop and Android Apps.
